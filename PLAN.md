## 1. Objective & System Changes

Track the time delta between when a child was checked out in Planning Center and
when our system actually fetched that checkout from the PC API.

Design decisions (already agreed with the product owner — do not revisit):

- **One new nullable column** `checkins.fetched_at DATETIME DEFAULT NULL`. Not a
  separate audit table: duplicate fetches are artifacts of out-of-order pagination,
  not real re-checkouts.
- **First fetch wins**: on upsert conflict, an existing non-NULL `fetched_at` is
  never overwritten. Implemented via `COALESCE(fetched_at, excluded.fetched_at)` so
  pre-existing NULL rows also get backfilled by later dupe fetches.
- **Timestamp originates in the PC API client**, not the fetcher worker: each
  `planningcenter.Checkout` carries `FetchedAt`, stamped inside
  `getFilteredResults` (once per call/page). Any client consumer gets it free.
- **Zero value stores NULL**, matching the existing `CheckedOutAt` convention in
  `CreateCheckin`.
- **Delta is derived at query time** (`fetched_at - checked_out_at`); nothing is
  denormalized and no UI/API display changes are in scope.
- `manual_checkins` is untouched (does not originate from Planning Center).
- All persisted timestamps are UTC (`time.Now().UTC()` / `.UTC()` before insert).
